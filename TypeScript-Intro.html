TypeScript Theory Notes

TypeScript is JavaScript with a static type system. These notes explain the ideas behind the syntax, with small examples you can adapt in real projects.

01

Core philosophy

JavaScript superset

Any valid JavaScript is valid TypeScript. Types are removed during compilation.

Compile-time safety

The compiler catches many mistakes before code reaches the browser or server.

No runtime type checking

Types do not exist at runtime. Validate data from APIs and users yourself.

02

Types and inference

Prefer inference when the initial value makes the type obvious. Add annotations at boundaries such as function parameters, exported values, and external data. 

let userName: string = "Ada";
const age = 36;                 // inferred as number
const isDeveloper: boolean = true;
const skills: string[] = ["TypeScript", "CSS"];
const scores: Array<number> = [95, 88];

// unknown is safe: narrow it before using it.
function printValue(value: unknown): void {
  if (typeof value === "string") console.log(value.toUpperCase());
}
Tip: Avoid any when possible. It disables type checking and allows unsafe operations.
03

Functions

Type parameters, arguments, and return values. Optional parameters must come after required ones.

function add(a: number, b: number): number {
  return a + b;
}

const formatUser = (name: string, role = "member"): string =>
  `${name} (${role})`;

function logMessage(message: string): void {
  console.log(message);
}

// A callback type
const numbers = [1, 2, 3];
const doubled = numbers.map((number: number): number => number * 2);
04

Objects, interfaces, and type aliases

Interfaces describe object shapes and can be extended. Type aliases are flexible and can represent unions, primitives, and tuples.

interface User {
  readonly id: number;
  name: string;
  email?: string; // optional property
}

interface Admin extends User {
  permissions: string[];
}

type Coordinates = [latitude: number, longitude: number];
type Status = "loading" | "success" | "error";

const admin: Admin = {
  id: 1,
  name: "Grace",
  permissions: ["manage-users"]
};
05

Unions and narrowing

A union allows more than one type. Narrow it with typeof, equality checks, the in operator, or a custom type predicate.

function formatId(id: string | number): string {
  return typeof id === "number" ? `#${id}` : id.toUpperCase();
}

type Circle = { kind: "circle"; radius: number };
type Square = { kind: "square"; side: number };
type Shape = Circle | Square;

function area(shape: Shape): number {
  if (shape.kind === "circle") return Math.PI * shape.radius ** 2;
  return shape.side ** 2;
}
06

Generics

Generics preserve the relationship between input and output types without falling back to any.

function first<T>(items: T[]): T | undefined {
  return items[0];
}

const firstName = first(["Ada", "Linus"]); // string | undefined
const firstScore = first([10, 20]);        // number | undefined

interface ApiResponse<T> {
  data: T;
  status: number;
}

const response: ApiResponse<User> = {
  data: admin,
  status: 200
};
07

Useful utility types

Partial<User>

Makes every property optional; useful for updates.

Pick<User, "name">

Creates a type with selected properties.

Omit<User, "id">

Removes selected properties.

Record<Status, string>

Builds an object type from known keys.

function updateUser(id: number, changes: Partial<User>): void {
  console.log(id, changes);
}

updateUser(1, { name: "Ada" });
08

Best practices checklist

  • ✓ Enable strict: true.
  • ✓ Prefer const and narrow unions.
  • ✓ Type API boundaries and validate runtime data.
  • ✓ Use descriptive aliases for domain concepts.
  • ✓ Keep type assertions rare and justified.
  • ✓ Let inference handle obvious local values.
